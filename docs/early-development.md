# 序盤の投資と予約の見通し

2026-10-13 / content `district-4`。メニュー・オープニングは引き続き後回し。
能動的な操作・計画は1ルート約20時間、初回EDまで現実4〜6週間という目標を維持する。
待つ時間を20時間へ数えず、最初の1時間は短い建設と並行計画、その後に長い予約へ移る。

## 今回の改善と仮値

- 工業地区の基礎費用を1,500→1,200 Cr、基礎工期を12→8分へ変更。
- 住宅Lv.2を「都市基盤の計画」で解放。住宅の新設350 Cr・5分、増強613 Cr・4分は維持。
- 他の地球地区Lv.2は自動化研究、地球Lv.3と火星の増強条件も維持。
- 都市整備12%/完成区画、初回開拓、隣接と効率上限は前の投資調整を維持。
- すでに支払った工業建設は旧工期のまま。未着手の予約から新価格を使う。

工業6分案、輸送研究の値下げ案も比較した。前者は住宅との工期差が薄くなり、後者は研究所が
先に資金を確保して工業が遅くなるため、今回は工業8分と住宅増強の早期解放を採用した。
研究や地区の種類を増やさず、税収・隣接を先に育てるか、製造効率・研究実証を先に得るかを選ぶ。

## 公開操作だけでの比較

初期900 Crから、同じ受注・研究・配置を使い、37.3分以降の投資順だけを変える。
初回住宅6.5分（先行受注1.5分+建設5分）、初輸送21分、初火星居住35分は共通。

| 経路 | 工業完成 | 住宅Lv.2完成 | 60分時点の資金 | 純収支/分 | 最長の判断間隔 |
| --- | --- | --- | --- | --- | --- |
| district-3の旧経路 | 58.76分 | なし | 3,037 Cr | +20 Cr | 21.46分 |
| 工業のみ・増強を保留 | 50.84分 | なし | 4,522 Cr | +20 Cr | 13.54分 |
| 工業→住宅増強 | 50.84分 | 56.03分 | 3,436 Cr | +37 Cr | 13.54分 |
| 住宅増強→工業 | 56.14分 | 42.80分 | 3,688 Cr | +37 Cr | 13.34分 |

住宅先行はこの経路では252 Cr多く残り、工業先行は製造効率と実証を5.3分早く得る。
増強を見送れば研究費を多く残せる。どの経路も全体最適とは扱わない。
増強経路は60分で6区画・総Lv.7・地球300人・火星24人になる。

最大約13分の空白は残る。これはスクリプト上の判断可能な時点を測った値で、
その間に人が配置比較を楽しめるか、能動20時間が成立するかは未実証。
全10研究・火星2都市の既存経路も再試走し、223.345時間（約9.306日）・48人に到達。
現在の試作範囲の経過時間であり、全球EDの所要時間ではない。
既存の増強/新設/新都市への3地区展開の比較も通過し、単発と集積後で利点が異なることを維持した。

## 触り方

1. 「研究ツリー」で都市基盤研究を完成させ、既存の住宅区画で増強を選ぶ。
2. 「設備・進行 → 稼働状況」で受注や増強の順序を↑↓で変更する。
3. 「予約の見通し」で30分・1時間・8時間後の資金、完成成果、各設備の進行・停止理由を見る。
4. 閉じて予約順を変え、再度試算して違いを確認する。

開始・予約済みの作業だけを既存エンジンで試算する。未予約の研究・建設・分岐選択は追加しない。
実世界と保存には触れず、試算を見ている間も通常の時間が進む。古くなった結果は自動で差し替えず、
見積時点と更新の案内を表示する。無期限反復で後続が始まらない理由も予約行に表示する。

## 再現と検証

```sh
mise exec -- bash tools/check.sh
mise exec -- dart run tools/verify_progression.dart
mise exec -- dart run tools/verify_investments.dart
```

純Dartの比較は資金注入なしの公開コマンドだけで進行。既存投資比較は条件を揃えた比較用状態を使う。
移行fixture `test/fixtures/district_v3.json` は旧 `9808084` のエンジンで作った工業建設2件の実保存。
支払済み12分工事と未着手の工事を区別し、ネイティブ/Web保存で成果・請求が重複しないことを検証する。

試算の局所検証は元状態・時計・保存・報酬の不変、時間一括/分割＋再開の一致、資金/資材不足、
研究実証/分岐待ち、有限/無期限反復、設備休止、完了履歴の上限を含む。
8時間試算の純Dart実測は通常の2受注で中央値約2ms、全125区画Lv.3・24予約・効率60%の比較用状態では
約412ms。毎秒試算せず、明示操作だけで実行する。端末での最大規模の応答性は今後測る。

UIレビューで、保存競合によって安全停止した後にダイアログの再試算が状態へアクセスする問題を検出。
競合後は再計算を無効にし、閉じる操作を残す回帰検証を追加した。

実施済み:

- `tools/check.sh`: 依存方向・整形・静的解析と147件のテストに成功。
- iPhone 17 Pro / iOS 26.1 Simulator: FlutterSceneの起動、見通しの期間変更・再計算・スクロール・閉じる、
  住宅Lv.2の早期増強、既存の都市配置・隣接・候補比較・保存再開が成功。操作テスト46秒、Simulator起動15秒。
- Chrome Web release: 1440×1000 / 844×390で8時間試算、固定操作、再計算、試算が実世界へ適用されないこと、
  予約順変更・オフライン再読込・複数タブ制御・報酬保持を確認。検証Nodeはcleanup後にPASSを出し、終了コード0で自然終了。
- 実画面を見て「定常収支＝税収−維持費」と受注の完了収入の違いを追記。その表示変更後もWidget5件とWeb実操作を再検証。
- iOSの初回試走とWebの初回試走では、検証ハーネスが一覧の先頭やChoiceChipのアクセシビリティ属性を正しく辿れず失敗。
  上へスクロールする操作とcheckbox role指定を修正し、両方の再実行で正常完走した。
