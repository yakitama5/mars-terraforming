# 都市・惑星の戦略試作

2026-10-13。今回の依頼をもとに、区画配置・隣接効果・球体の惑星・研究ツリーを一緒に改善する。
元の企画書を完成UIの仕様として固定せず、ここに試作時の判断と検証を記録する。

## 今回の確定した方向

- 地球の財政・産業を火星開発へつなぐ。外部受注と自前の建設・製造・輸送が同じ設備を使う。
- 惑星全体から都市を選び、都市内の区画へ地区を配置する。完成後は都市の見た目も発展する。
- 場所・周囲の地区・研究投資によって収益と工程時間が変わる。数字だけを増やす操作にしない。
- 日本語・横画面・iOS先行。PCのWeb版でも同じゲームを試せる。
- メニュー・設定・オープニング・チュートリアルはゲーム部分が固まってから。
- 全球環境、ED、周回、火星復元、収益化は今回扱わない。未決定のルールを先に確定しない。

## 仮採用した遊び方

1. **惑星マップ**：地球／火星を切り替え、都市と次の研究で開く候補地を見る。球体を回転・拡大できる。
2. **都市開発**：六角区画を選ぶ。地形、隣接する地区、建設費、期間、収益・効率の変化を比較して予約する。
3. **研究ツリー**：都市・産業、輸送、居住・現地生産のつながりと解放内容を見る。投資する枝と順番を決める。
4. **設備・進行**：外部受注で稼ぎ、研究・製造・輸送・地区建設へ振り分ける。停止理由を確認し、次の予約を前後へ動かす。

惑星上の建物は都市の発展度を示す模式表現で、区画配置の縮尺どおりではない。
地形と大陸・クレーターも視認性のための簡略図であり、実際の地形測量データではない。

## 調整対象の数値とルール

- 地球2都市、火星3都市。各都市5×5の25区画。奇数行をずらす六角配置で、隣接は最大6区画。
- 9種の地区、最大Lv.3。25区画は有限で、増強には研究と追加費用が必要。
- 地形は平地・海岸・高台・鉱床・氷層・クレーター。地形に適した地区を選び、隣接効果も比較する。
- 研究所は共用1列。新しい研究は都市・産業／輸送／居住の3系統をつなぎ、4〜48時間を基礎工期とする。
- 地区の効率は共用設備へ作用する。効率+20%なら工期を1.2で割る。効率上限は対応する研究段階で30→45→60%へ拡張する。
- 工期は着手・支払時点で固定する。建設完了による効率上昇は次に開始する作業から適用する。
- 発電地区は隣接する研究・工業・宇宙港へ効果を渡す。工業の近隣では住宅税収が下がる。
- 地区の維持費と効果は対応する設備の稼働に連動する。資金不足では設備を休止し、基礎税収で再建できる。
- 火星の新しい地区建設・増強には輸送した居住キットを使う。一括製造・輸送の研究もあり、設備の順番が重要になる。
- 更地化・移転は未実装。未着手の予約は取り消せる。支払済みの1回は最後まで実行する。
- 初期の短い生命維持・製造・輸送は導入として維持。旧住宅拡張・旧居住区建設の新規UIは都市の区画配置へ置き換える。
- 初回ED4〜6週間は完成ゲームの目標。今回の地区・研究の追加だけで、その期間全体やEDが完成したとは扱わない。
- 開発用時間送りは+5分・+1時間・+1日。通常時間とデータは分離し、通常版にボタンを表示しない。

数値の正本は `lib/domain/game_content.dart`。研究の解説では実証・構想・ゲーム上の仮定を分ける。
隣接ボーナスや施設効率の数値はゲーム上の仮定であり、現実の科学的効果量ではない。

## 改善2巡目：現地開発と研究投資

第1版では、地球の初期受注2種を放置するだけで火星へ行かずに全研究が進み、
研究地区4＋発電2の6区画で効率上限60%に達した。通常操作の純Dart試走で確認した。

そのため研究の実証条件を追加した。研究済みの成果は取り消さず、未着手予約は条件待ちになり、
必要な地区の完成後に自動着手する。

| 研究 | 必要な実証 |
| --- | --- |
| 自動化生産 | 工業地区1か所 |
| 軌道補給網 | 宇宙港地区1か所 |
| 閉鎖循環 | 火星居住施設1か所（旧居住区も含む） |
| 現地資源利用 | 温室地区1か所 |
| 地域の閉鎖居住網 | 火星で整備済みの2都市と資源採取地区1か所 |

新規研究費を初期受注の純収益と対比して調整し、合計は生命維持を含め5,014,180 Cr。
初期7工程の費用・工期・報酬は保持した。新研究は4,000〜1,800,000 Cr、詳細はデータ定義を参照。
隣接による効率値も縮小し、効率上限を研究段階で30→45→60%へ伸ばす。
上位受注・都市の税収・一括輸送の研究に投資する価値を持たせる。
増強の費用/工期倍率4倍・12倍は今回維持したが、別都市の新区画と比べた価値は次の調整対象。

## 既存セーブの扱い

進行データはschema 2 / content `district-2`。schema 1 / `prototype-1` を読み込んで移行する。
ファイルとブラウザの保存コンテナ形式は従来のまま。世代・チェックサム・前回保存への回復は継続する。

旧市街と旧居住区は区画外の既存施設として人口・収入・施設数を保持する。新しい区画を勝手に埋めず、
新地区の人口や税収を重複して与えない。着手済み作業の残り時間、支払、反復、研究、実績報酬も引き継ぐ。
`test/fixtures/prototype_v1.json` はコミット `1a2d52c` の旧エンジンで作った、
初居住の実績と進行中の受注を含む実データ。ネイティブ・ブラウザ両保存方式で再開を検証する。

### 実施済みの検証

- `mise exec -- bash tools/check.sh`: 依存方向・整形・静的解析に問題なし、**108テスト成功**。
  時間の一括/分割、時計前後退、資金・資材不足、反復・分岐待ち、異常終了時の保存回復、
  旧保存移行、二重付与防止も含む。地域と研究に関する追加テストは別ファイルへ分けた。
- `mise exec -- dart run tools/verify_progression.dart`: 所持金・技術・資材を注入せず、
  予約・並べ替え・時間経過・分岐選択で全10研究と火星2都市へ到達。
  経過 **253.386時間（約10.56日）**、48人、居住キット3、1,296,039 Cr。
  これは1つの検証経路であり、最短経路でも完成ゲームのED所要日数でもない。
  デッドロック、30日超過、保存再開による差異は失敗として扱う。
- Web releaseビルド成功。Chrome 154 / Playwright 1.57 / Node 26.5で
  `tools/web_smoke.cjs` が**終了コード0で自然終了**。研究→製造→輸送→地区居住、
  受注との順序変更、支払済み作業の継続、再読込、複数タブのロック、オフライン再読込、
  外部ホストへ依存しないこと、844×390での固定ボタン・ツリー全体表示を確認。
  手動終了や `process.exit(0)` による成功扱いはしていない。
- iPhone 17 Pro / iOS 26.1 Simulatorで `flutter drive` 成功（35秒の操作テスト）。
  FlutterScene実描画、惑星切替、研究ツリー、予約順変更、地球の住宅と隣接研究地区、
  表示プレビューと完成後の税収・効率の一致、火星居住、保存再開を確認。
  一時保存先を使い、利用者の通常/開発用セーブは変更しない。
- 独立した読み取りレビューで、移行・予約・実証条件・隣接計算・描画更新に重大な回帰の指摘なし。
  レビューは実行検証の代用にしていない。

### 残る制約と次の改善判断

- 実機iPhone、Android、Safari、数週間連続した実時間運用は未検証。
  30fps上限・pixel ratio上限2を指定したが、密集した後半都市の持続性能は未計測。
- iOSで最初のシェーダー準備が約2.2秒かかったログを確認。初回表示の引っ掛かりが残る。
  メニュー作成とは分け、ロード時の事前描画を今後検討する。
- 全体表示時の研究ノードは小さくなる。拡大・ドラッグと選択詳細を併用する設計だが、
  実機での指の操作感と文字の読みやすさは継続調整する。
- Lv.2/3の増強と新都市への展開の価格差、住宅・工業の配置の取捨選択、
  各研究系統へ先行投資した際の収益差を次の比較対象にする。数値は確定仕様ではない。
- 更地化・移転・独立した移住操作は未実装。長期の全球環境改変・EDも未実装。
  初回ED4〜6週間を満たしたとは扱わず、次の遊べる段階を足して調整する。
- メニュー・設定・オープニング・チュートリアルは保留。まず今回の4画面で配置と設備配分を試し、
  分かりにくい操作と戦略上の選択肢を改善する。
