# 未来序章のオリジナルBGM

作成: 2026-10-16。ユーザー依頼に合わせ、40秒・5章の3D OPに同期する音楽を新規作成した。
素材は [opening_music.wav](../assets/audio/opening_music.wav)、再現コードは
[generate_opening_music.py](../tools/generate_opening_music.py)。アプリ側の再生・停止・音声との同期は別実装で扱う。

## 曲の構成

仮題「Blue Horizon — First Light」。Dを中心とした和声にadd9・maj7・sus4を使い、
大きな技術の進歩と、暮らしへ戻る温かさを表す。120 BPM・4/4の20小節で、
半拍のゆったりした流れを基本とする。歌詞・歌声はない。

| 時間 | 画面 | 音楽の役割 |
| --- | --- | --- |
| 0–8秒 | 都市開発 | 柔らかなパッドと少ない鍵盤音。明かりが増えるように徐々に広がる |
| 8–16秒 | ロケット打上 | 弦の倍音・低い膜音・鍵盤の反復を足し、上昇感を作る |
| 16–24秒 | 月面基地 | 打楽器と反復を引き、薄い和声と遠いベルで空間を開ける |
| 24–32秒 | 火星探査 | 鍵盤の小さな反復と柔らかい脈動が戻り、調査の前進を示す |
| 32–40秒 | 火星移住 | 弦が戻り、G→A→Dの終止へ。36秒からの最終和音と残響を静かに収める |

全音色はコードから生成する。微小に音程の異なる3声、倍音別の音量、緩い揺れ、
柔らかな立ち上がりで、単一の正弦波を鳴らすだけの音を避けた。
鍵盤はフェルトピアノを思わせる減衰と少量の打鍵ノイズ、ベルは不調和倍音、
打楽器は低い膜の振動と帯域を絞ったノイズを使う。残響も独自の初期反射と減衰ノイズから合成した。
本物の弦楽器・ピアノの録音や、専用オーケストラ音源の再現ではない。

ナレーション用に低中域を主体とし、約2.3kHzを中心とする広い帯域を控えた。
母音・子音が必ず明瞭になることを単体の音源だけで保証せず、実際の声と重ねて最終調整する。
このWAVは全体RMSが-24dBFSの素材。まず再生gain 0.65〜0.8を候補に、声との釣り合いを確認する。
章ごとの編成差は意図したもので、月では打上げより約5.9dB静かになる。

## 由来と再現

- この作業で新しく組み立てた和声・旋律・波形。既存楽曲の採譜や録音の切り出しはしていない。
- 外部音源、SoundFont、既存の残響IR、商用サンプル、音楽生成サービス、ネットから取得した素材は使っていない。
- 生成時だけPythonとNumPyを使用。アプリ実行時にPythonや追加サービスは不要。
- 確認環境: Python 3.12.14、NumPy 2.3.5。乱数はPCG64の固定seed `2026101601`。
  この環境で2回生成し、WAV全体のSHA-256が一致することを確認した。
  異なるCPU・数学ライブラリ・NumPy版でのバイト単位一致までは保証しない。
- 新しい外部音源ライセンスは追加しない。生成スクリプトと音声の取り扱いはこのプロジェクトの方針に従う。

```sh
python3 tools/generate_opening_music.py
python3 tools/generate_opening_music.py --verify
```

NumPy 2.3.5のあるPython環境を使用する。この作業では既存のCodex同梱Pythonを使い、
追加インストールやアプリの依存変更は行っていない。
別出力先を指定する場合は `--output /path/to/opening_music.wav` を付ける。
生成後は長さ・形式・音量・末尾を自動検査し、結果をJSONで表示する。

## ルナの英語ナレーションとの合成・公開

[mix_opening_audio.py](../tools/mix_opening_audio.py) を追加した。現在は声が未生成なので、
実際のカタログは引き続きBGMだけを指す。代用の声や無音の音声ファイルは配布に入れていない。

```sh
# 全10本が実際に生成され、検査に通った後で実行する。
python3 tools/mix_opening_audio.py --check-only --preview /private/tmp/opening_mix.wav
python3 tools/mix_opening_audio.py
```

- 台本のOP5本と初回案内5本の存在、重複しないID、PCM16・1〜2ch・8〜96kHz、
  ヘッダのフレーム数と実データ長、時間上限、無音に近い波形・クリップを検査する。
  さらに生成記録の全件完了、モデル・声・台本SHAと各WAVのSHA一致を要求する。
- OPは各章の開始から0.7秒後、すなわち0.7 / 8.7 / 16.7 / 24.7 / 32.7秒へ配置。
  1本最大6.6秒。尺を押し込めるために速度や音程は変えず、超過した声は公開前に拒否する。
  64タップの窓付きsincで44.1kHzへ変換し、monoは左右へ同じ声を置く。
- OPの声は活動区間RMS -20dBFSを目標に整え、声単体のピークを-6dBFS以内にする。
  BGM gainは0.8、語りの180ms前から6dB下げ、語りの後450msで戻す。
  素材の全体gainでピークの余裕を確保し、最終PCMと4倍補間のピークも検査する。
  初回案内の単独音声は生成されたPCMをそのまま同梱し、OP用の音量調整を上書きしない。

2ファイルを同時に置き換える原子操作はないため、公開の基準を`catalog.json`に一本化する。
ミックスは `assets/audio/opening_mix.<SHA-256>.wav`、声は
`assets/audio/luna/<ID>.<SHA-256>.wav` という不変の名前で先に書き込む。
全素材が保存された後にカタログを同ディレクトリの一時ファイルから原子的に置換する。
失敗・プロセス中断で未参照の新素材が残ることはあるが、旧カタログが指す素材は変更しない。
現在の`opening_music.wav`も書き換えない。固定名`opening_mix.wav`は確認用に配布外へ出力でき、
同じ40秒WAVを二重に配布しない。OS電源断時のディレクトリ永続化まで保証する仕組みではない。

音声生成側も、現在の台本・モデル・声・WAVのSHAが過去の検証記録と一致するときだけ再利用する。
台本や声の変更時には`--force`で明示的に再生成する。1本ずつ検査後に部分的な生成記録を残し、
中断後は確認済みの声だけを再利用する。検証記録のない残存ファイルは新しい声として扱わず再生成する。
`generateContent`の送信形式は、対応する[公式のLegacy TTS資料](https://ai.google.dev/gemini-api/docs/generate-content/speech-generation?hl=en)と照合した。
API方式の変更は行っていない。

検証はすべて`/private/tmp`内の明示的な合成波形で実施し、実際の声として扱っていない。
欠損、途中で切れたPCM、6.6秒超過、クリップ、由来の不一致で公開を拒否することを確認した。
24kHz monoと48kHz stereoの混在、最終章6.6秒、40秒stereo合成、末尾50msの無音も成功。
カタログ書込失敗を注入して旧カタログ・旧音源が不変であることと、再公開後も旧世代が残ることを確認した。
生成側は再利用・検査のみ・台本変更時の拒否・`--force`・3本後の中断から残り7本の再開を確認した。
実リポジトリでの検査コマンドは`opening_01`未生成で停止し、BGMとカタログを保持した。
今回の検証ではAPIリクエスト、APIキーの使用、Flutter実行、実際の英語の発音・声色の評価は行っていない。
