# 地形上の都市開発と指令画面

更新: 2026-10-14。ユーザーの「CS機の戦略ゲームらしいUI」「実際の地形に六角区画を重ね、建設を3Dへ反映」という要望による改善。
完成UIの固定ではなく、次の試遊でレイアウトと地形表現を調整するための実装。
ゲーム進行・費用・期間・保存形式は district-5 を維持する。

## 画面と操作

- 上部は資金、毎分収支、人員、技術力などの国力HUD。下部は惑星・都市・研究・設備・機関の開発指令。
  広い画面は友好・宇宙貢献も表示し、小さい横画面では「機関運営」で全指標を確認する。
- 全球で都市を選び「都市を開く・区画を計画」から地域へ移る。都市画面の地球アイコンで全球へ戻る。
- 地域は起伏・海岸・鉱床・氷・クレーターを持つ3D地形。地形上の六角区画を選択し、右で用途・費用・期間・隣接効果を確認して予約する。
- 地表ドラッグでパン、ピンチ／ホイール／±で拡大縮小、左右の回転ボタンで向きを変える。
  コンパスで視点を戻す。都市名の横の拡大アイコンで詳細を閉じて地図を広く表示し、区画選択で詳細を開く。
- 工事中の区画では現在の残時間・進捗・停止理由を先に表示する。着工時に固定した工期を使い、現在の効率で再見積もりした時間と混同しない。「設備・進行で確認」から予約順へ移れる。
- メニュー、オープニング、課金やゲームパッド操作は今回の追加範囲に含めない。iOS先行・横画面・タッチ操作の方針を維持する。

## 地形と建物の対応

既存の各都市5×5=25区画、row-majorのplotIndexとodd-rowの六角隣接関係を維持する。
地形・六角境界・クリック判定・施設の位置に共通のワールド座標とカメラを使う。
地形は各都市のゲームデータから作る架空の地域で、地球／火星の実測標高やGIS地図ではない。

| ゲーム状態 | 地図上の表示 |
| --- | --- |
| 空地 | 地形と自然地物。選択や見積もりだけでは施設が現れない |
| 未着工の予約 | 敷地の旗。資金・条件不足でも完成施設にはしない |
| 着工済み | 基礎、骨組み、クレーン、進捗。設備休止時も途中工事を保持 |
| 完成 | 同じ都市・区画へ用途別の施設を配置 |
| 増強中 | 既存Lvの施設を残し、工事設備を重ねる |
| 増強完了 | 同じ場所で棟数・高さ・翼・設備を追加 |

住宅は建物群、研究は棟とアンテナ、工業は工場・煙突、発電はパネル、宇宙港はロケット・発射台、
火星居住はドーム／地下入口、温室は栽培棟、採掘は櫓・タンクとして描く。隣接する完成地区間には道路を表示する。
初期の本部・市街はデルタ湾岸の区画外の装飾として表し、建設可能な区画や税収を勝手に増やさない。
保存上の地区用途・位置・Lvを描画へ写すため、都市切替・再開後も同じ状態へ戻る。

## 層の分離と描画負荷

- `presentation/city_scene_data.dart` が進行状態を表示専用 `ScenePlot` へ変換する。
- `rendering/city_geometry.dart` が地形・投影・六角判定、`city_models.dart` が用途別モデル、`city_scene.dart` がカメラと入力を受け持つ。
- renderingはdomainやcontrollerを参照せず、収支・隣接効果・時間を計算しない。
- 地形は地形データ変更時、施設モデルは用途／Lv／工事段階変更時だけ生成する。毎秒の残時間や進捗は2D表示で更新する。
- FlutterSceneは30fps、pixelRatioは最大2。起動待ちやGPUエラー時は同じ投影による簡易地図を表示し、エラー時は再試行を案内する。これはWebだけを2D化する構成ではない。
- Flutter 3.47.7、FlutterScene 0.24.3と既存lockfileを継続。外部の画像・地形・フォント配信は追加しない。

## 確認と改善

自動検証では次を対象にする。

- 5都市×25区画の描画座標と隣接6方向・共有辺の整合。複数のカメラ方向と画面サイズで中心の投影先を選択できること。
- 六角外の矩形部分、地形外・画面外が別区画として選ばれないこと。
- 予約・工事・休止・完成・増強・保存再開の対応。読み取りだけで進行や保存を書き換えないこと。
- 844×390／1280×800で地面座標タップ、パンで誤選択しないこと、地図を広げてから区画選択・確定までの操作。
- WebとiOSで地表の実座標をタップし、選択した区画番号と予約先を照合。工事前・工事中・完成・増強を撮影する。

初回の幾何検証で、クレーターの最近傍区画が変わる位置に約0.085 world unitの高さ不連続を発見。
クレーター中心からの連続した距離場へ修正し、共有辺と境界直前／直後の回帰試験を追加した。
Vector3のFloat32座標は1e-5 world unitの許容差で照合する。

独立レビューで、GPUを使えない場合だけ初期の建物スナップショットが残る問題も検出した。
簡易地図へ最新の区画状態を渡し、空地→完成→増強で地表レイヤーの建物画素が増える回帰試験を追加した。
Webの通信検査では、新しいChip／FilledButtonの文字スタイルが同梱フォントを継承しない問題を検出。
コンポーネントの明示スタイルにもNotoSansJPを指定し、外部フォントへの依存を除いた。

### 実施した検証

- `bash tools/check.sh`: 依存方向・整形・静的解析に問題なし、192件のテスト成功。
- iPhone 17 Pro / iOS 26.1 Simulatorの`flutter drive`: 地表の3地点の実座標タップ、建設→完成→Lv2増強、隣接研究地区、都市切替、火星居住、保存再開まで成功。
  統合テストは1分09秒で完了し、ドライバも終了コード0で終了した。
- `tools/web_smoke.cjs`: Chromeの実WebGL描画で地表3地点の選択、火星居住施設の工事→完成、地球住宅、投資比較、研究・設備配分・提携・人員まで成功。
  1440×1000と844×390、オフラインでの完全再読込、複数タブの排他、保存の継続を確認。通信先はローカルの配信元だけで、外部フォント要求なし。Nodeは手動終了せず終了コード0。

### 残る確認

- iOS実機・Androidは未実施。小さい横画面の指操作とGPU負荷は実機で継続確認する。
- Simulatorで初回の描画パイプライン生成に最大約2.3秒の警告が出た。定常時の操作は完走したが、初回表示の待ち時間と実機fpsは改善対象。
- 地形・施設の造形・地区密度は仮表現。既存の費用・工期・隣接ルール・セーブを保持し、今回の見た目だけで進行や報酬を増やさない。

## 参考にした設計原則

[信長の野望・創造の公式システム紹介](https://www.gamecity.ne.jp/souzou/system.html)は、重点産業で城下町の外観が変わることを説明している。
[戦国立志伝の公式内政紹介](https://www.gamecity.ne.jp/souzou/sr/system.html)では、水源・街道・資源の立地や隣接施設が内政の判断につながる。
[Civilization VIの公式紹介](https://civilization.2k.com/en-GB/civ-vi/)では、都市が周辺の地形へ広がる構成が示されている。
これらを参考に「地形を見て配置し、完成が同じ地図へ現れる」導線へまとめた。本作向けの設計判断であり、画面やアセット、個別のゲームルールの複製ではない。

次の試遊では、地形の見分けやすさ、施設の密度、指令パネルの情報量、指でのパン・選択・拡大のしやすさを確認する。
