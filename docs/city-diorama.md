# 街を近くから眺める箱庭景観

更新: 2026-10-14。前回の [六角地形と街区配置](district-landscape.md) に続く改善。
このページは当時の記録。2026-10-15に [円形の箱庭](circular-terrarium.md) へ更新し、
初期視点は全景、全域倍率は0.70へ変更した。接写・素材・投影影の基盤は継続する。
ユーザーから「もっと箱庭感」「Civilizationのような質感」と指摘を受け、
広い地図へ小模型を並べた印象を、敷地・街路・建物を近くから眺める構成へ変えた。
提供された参考画像は構図・密度・接地感の参考にとどめ、画像や他作品のアセットは組み込んでいない。

## 画面を比較して直した点

| 前版の実画面での課題 | 今回の変更 |
| --- | --- |
| 全域表示が初期状態で、街が小さい | 低い俯角の接写から開始。「市街」と「全域」を文字で切り替え |
| 地面の三角形と平坦な色面が目立つ | 頂点を共有した地形・滑らかな法線・微細な地表の色と凹凸・波のある水面 |
| 木と建物が地面から浮いて見える | 太陽光による投影影、壁際や根元の接地陰影。静止した形状の影を再利用 |
| 住宅が同じ小箱の集合に見える | 住宅10/12/14棟の仮表現。勾配屋根・軒・煙突・個別窓・窓台・入口庇 |
| 建物以外の街の要素が少ない | 歩道・車・街灯・中庭・植え込み・花壇・ベンチ・広葉樹 |
| 設備の用途を読み取りにくい | 研究棟のガラス面と中庭、工場ヤードと容器、太陽光パネルのセル、ドームと温室のフレーム |

最初のWeb比較では地表模様が筋状に見えたため、ノイズの生成と強さを修正。
投影影は最初の設定では弱く、面の取り扱いと環境光への影の効き方を調整して再比較した。
静的な影の再利用を切った画面と有効な画面も、同じ検証用の都市で比較した。

## 操作

- 「都市開発」→施設→六角の土地→「この区画に建設を予約」は維持。
- **市街**：選択した区画へ寄る。未選択なら中央へ戻る。
- **全域**：25区画をまとめて表示。端の土地を選び、市街へ寄ることもできる。
- ドラッグで移動、ホイール／ピンチ／±で拡大縮小。
- 右端の視点ボタンから左右回転と中央への復帰。2本指でも回転可能。
- 「地図を広く表示」で右側の情報欄を閉じる。建設には情報欄を開いて明示確定が必要。

## 実装・仮値

地形の座標・六角の投影・入力判定は共有。建設予約中は自然物を残し、着工時に除き、
増強中は既存地区を残す。進捗の数値更新だけではメッシュを再生成しない。
建物と自然物はまとめたメッシュ、地表素材は256角の小さな画像をコードで生成する。
ネットワークや追加アセットのダウンロードを必要としない。
地形と地表材質、モデル、視点は描画層に限定し、進行処理を複製しない。

接写の倍率2.3、俯角0.60ラジアン、最大倍率3.2、全域倍率0.9は仮値。
影は1024角1枚、接地陰影は半解像度。画面更新上限30fpsは設定値であり、実機での達成値ではない。
ガラスは不透明の光沢材質で、透過・屈折は未実装。車や住民の交通シミュレーションは追加していない。
棟数・舗装・樹木・地形・色・影の強さは見た目の仮設定で、費用・収益・人口に影響しない。

Flutter 3.47.7 / FlutterScene 0.24.3、lockfile、content district-5、保存形式2を維持。
進行・収支・研究・施設ID・建設可能条件・隣接効果・保存形式の変更なし。

## 検証

- `bash tools/check.sh`：依存方向、整形、解析に問題なし。203件成功。
  接写で中心と隣接の区画、全域で全25区画、拡大して端へ移動した際の投影・選択を確認。
- ChromeのWebGL描画で住宅・研究・発電・工業・住宅の5地区を実操作で建設。
  予約取消、増強と新都市の比較、火星居住、設備配分、人員と提携、保存再開、二重報酬防止、
  別タブ排他、オフライン完全再読込を確認。外部ホストへの要求なし、Node自然終了0。
- 初回Web検証が新しい市街／全域ボタンからの外部フォント要求を検知。
  ボタンの独立TextStyleでfontFamilyが落ちていたため、テーマの同梱フォントを継承するよう修正。
  検証はpageerrorに加え、シェーダー・パイプライン失敗による描画省略のconsoleログも検出する。
- 最終Web版で「全域」から端の区画を選び、「市街」で寄り、回転した後も同じ区画を選べることを確認。
  カメラ操作前後で施設と予約のIDが変わらないことも確認。Node自然終了0。
- iPhone 17 Pro / iOS 26.1 Simulatorの実GPUで最終の倍率2.3を確認。
  全域の地表3地点をタップ→住宅建設→Lv.2増強→隣接研究地区→選択区画へ接写→
  パネルを閉じて拡大→都市比較→火星居住→保存再開が成功。統合試験1分18秒、ドライバ自然終了0。
  [iOSの接写](screenshots/diorama-ios-close.png)。初回パイプライン生成は最大約0.80秒、
  影用の初回生成も約0.44秒の警告あり。初回コンパイルの停止を完全には解消していない。

Web再現は `bash tools/build_web_preview.sh` → `site-preview/dist` をHTTP配信 →
`node tools/web_smoke.cjs`。環境変数は [Web検証ガイド](web-preview.md) を参照。
`MARS_SCREENSHOT_DIR` で画像の出力先を指定可能。
任意の `MARS_VISUAL_STATE=/tmp/city-visual-state.json` は、この検証が実操作で作った都市のセーブだけを
書き出し、同じ都市を使った見た目の反復比較に利用できる。ユーザーのブラウザプロファイルは使わない。

## 残る課題

iOS実機・Androidの負荷と電池消費、長時間のGPUメモリ推移、Safari/Firefoxは未検証。
小さな横画面では文字欄との両立が必要で、細部を見るには接写・パネル開閉を使う。
次は敷地の密度と屋根・自然物の質感を試遊で確かめ、必要に応じて画面構成を調整する。
今回の状態をCivilizationと同等の描画品質や、最終の美術仕様と判定しない。

1ルートの累計操作約20時間・初回4〜6週間・最初の1時間は連続して判断する方針を維持。
今回の景観変更は、その長期バランスの達成確認には含めない。メニュー、オープニング、ED、周回は後段。
