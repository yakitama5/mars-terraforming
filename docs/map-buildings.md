# 研究施設を地図へ建てる実装

更新: 2026-10-21。優先12系統の実装と内部テスト配信の記録。
[拡張案](city-building-expansion-proposal.md)に対する今回のユーザー依頼を起点とする。

## 今回の依頼

優先12系統を地図で建設できるようにし、見た目と役割を読み取れる形にする。
実在技術や近未来の構想も、ゲーム上の選択に結び付く範囲で採用する。
検証、コミット、developとmainへの反映、Android/iOSの内部テスト配信までを今回の範囲とする。
直前の「企画だけ」という指示は、この実装依頼で更新された。

専用worktreeで実装・ローカル検証済み。元のブランチと未コミット変更を保持する。
基点はdevelop `f76039f360ef92290b6915f8cd0dd0827964a911`。
実装内容・仮値・保存移行・検証結果・配信結果を、確定した順にこの文書へ追記する。

## 優先12系統と仕事

| 研究 | 地図の施設 | 固有の仕事 |
| --- | --- | --- |
| B01 | 水耕温室 | 処理水から食品を生産。実験への研究者配分と生産量を比較 |
| B13 | 食品検査・保管棟 | 食品から検査済み補給品を作り、品質指定受注やキット製造に使う |
| R01 | 資源分析所 | 指定した都市区画の適性を記録。調査報酬は一度だけ。調査済み氷層の採水量を改善 |
| R05 | 採氷区 | 月・火星の氷層に配置し、原水を採取 |
| R07 | 水処理棟 | 原水を処理水へ加工。採氷と原水搬入の入口を選ぶ |
| R15 | 部品造形工房 | 原料から認定交換部品を製造。製造・整備へ供給 |
| E09 | 蓄電池棟 | 基礎電源や発電地区の余力で充電し、不足する工程電力を有限放電で補う |
| E10 | 水電解・ガス貯蔵棟 | 処理水を対応する水素・酸素へ加工。月面シャトルの準備へ使う |
| E13 | 配電センター | 部品を使って同市の発電地区を接続。センター自体は発電しない |
| M08 | 整備センター | 部品から整備済み交換セットを作り、回収機整備・製造へ供給 |
| M25 | 再使用機の回収・整備棟 | 部品/交換セットで機体を準備し、火星へ貨物輸送。次便には再整備が必要 |
| M13 | 月面シャトル整備棟 | 月面で機体を整備・充填し、月周辺軌道から月面への補給を反復 |

R16材料回収の研究後は、造形工房へ廃部品の再成形を追加する。
回収損失を持ち、投入した部品を超えて材料が循環増殖するものにはしない。
基礎研究所は既存本部の地図上の入口から確認でき、初期の研究者と共通RPを参照する。
研究者のいない専門研究設備からRPは発生しない。

これらは既存14地区の土台と併存する。98研究や地球/月/火星のモデル違いを、独立した建物の数へ単純加算しない。

追加施設はGameContentの施設定義へ研究ID・配置条件・仕事IDを登録し、
共通の予約・費用・人員・在庫・保存処理と都市別インスタンスを利用する。
仕事の入力/出力・役割と外観を増やし、単なる倍率違いの建物を量産する形にはしない。
固有モデルはrenderingへ追加し、UIや描画へ進行計算を複製しない。

## 建設・見た目・運営

研究完了後にだけ候補へ現れ、研究の詳細や導入一覧から都市地図へ移れる。
区画と建設位置を指定し、費用・工期・維持費・現地資材を確認して予約する。
月・火星の新設は現地の居住キット1基を着工時に消費する。在庫0でも予約し、通常貨物便の到着を待てる。
研究完了や移設では徴収せず、支払い済みの旧工程にも追加徴収しない。
通常施設は1区画2棟まで。採氷区・回収整備棟・月面シャトル整備棟は区画専有。
既存の研究/工業/通常発電/現地研究地区は1枠を使い、住宅や宇宙港等は専有する。
各系統は1都市1棟を基本とし、同じ系統を別都市へ建てられる。

温室の透明屋根、検査倉庫と搬入口、掘削塔、分離槽、造形棟、電池列、別々のガスタンク、配電盤、
整備アーム、横置きロケット、月面着陸機など、主要な輪郭を変える。
建設は段階的な足場、完成後は稼働/休止、機体は出発中の不在を同じ位置に反映する。
大型格納庫と整備ヤードは敷地内の最高地形へ土台を合わせ、基礎柱を追加する。
クレーターの縁に機体や脚が埋まらないことを月面の実描画で確認した。
全景では区画を選び、接写では建物や建設位置を十分な大きさの領域から選べる。

実画面: [2棟の併設](screenshots/buildings-ios-two-sites.png)、
[回収・整備棟](screenshots/buildings-ios-reusable-rocket.png)、
[月面整備基地](screenshots/buildings-ios-moon-shuttle.png)。研究と資材を投入した描画用fixture。

仕事は既存の工場・研究所・宇宙港の作業枠を共用し、受注や自前輸送と競合する。
担当者・研究者・機体・電力・入力在庫を二重使用しない。
資金不足や入力不足には理由を示す。水・食品・原料・部品・対応推進剤の搬入手段を残し、全施設の建設を入口に要求しない。
地球の部品・検査済み補給品・交換セットは、居住キット製造で費用を軽減する用途を持つ。

局所の在庫と電力の単位はゲーム用の尺度。水素/酸素の数値は実際の質量比を再現していない。
月面便は地球側の搬入と月周辺軌道からの降下・帰還を一工程へ簡略化し、月面シャトルを火星行き機体とは扱わない。

調整値の主なものは、通常2枠、基礎電源2、接続した発電地区1件につき電力4、蓄電容量20、
通常在庫の上限1,000、調査36RP/区画、調査済み氷層の原水+2/採水工程。
地球のキット製造では部品40・補給品20・整備セット30ドルを、それぞれ対応在庫1単位の消費で軽減する。
品質指定受注は補給品を使い1,200ドルを受け取る。部品造形90秒、水電解60秒とし、
単純搬入に対して安価な現地生産を、電源・担当者・設備投資との比較で選べるようにした。
再使用機と月面シャトルは3キットをまとめて運ぶ。少量の通常便を残し、大口便では再整備と在庫を準備して
1基あたりの費用と宇宙港占有時間を抑える。
同時稼働の設備上限は複数都市への展開に合わせ12から24へ拡張し、維持費と人員の負担を残す。
これらは物理性能や採算から導いた値ではなくGameContentの仮値。

## 保存と移行

schema 2を維持し、contentをdistrict-10へ更新する。
設備の資産・有効状態・研究者の台帳を共有し、新しい棟には個別IDを付ける。
既存の技術IDを使う導入済み設備と支払い済み工程は保持し、二重の能力・人員・報酬を付けない。
旧設備は既存敷地として地図から確認でき、再購入せずに新しい区画へ配置し直せる。
月技術の地上実証を、月面の完成施設へ自動変換しない。

配置・建設/移設の予約・入力消費・凍結した工程成果・蓄電使用・機体準備・一度限りの調査記録を保存対象とする。
新しい保存の不正な位置や在庫は、正常な前世代へ回復できるよう読み込みで検出する。

## 実在技術と近未来の構想の扱い

研究カタログと[出典台帳](research-literature.md)の範囲を引き継ぐ。
追加確認では、部品の現地製造、水回収から電解への工程、電源の共用を、次の一次資料と照合した。

| 資料 | 確認した範囲 | ゲーム側で置く仮定 |
| --- | --- | --- |
| NASA [Long Duration Space Flight with 3D Printing](https://www.nasa.gov/missions/station/solving-the-challenges-of-long-duration-space-flight-with-3d-printing/) | ISSの樹脂部品造形と再生原料の実証、部品検査の必要性 | 造形工房の能力・製造費・適合部品はゲーム用に簡略化。全機材を現地製造できるとはしない |
| NASA/NTRS [Propellant From Lunar Water](https://ntrs.nasa.gov/citations/20230005189) | 2023年の会議要旨。抽出・捕集・精製・水電解を一連の系として比較する構想 | 月面設備の実稼働や実採算の証明ではない。ゲーム上の輸入/自製の比較へ用いる |
| DOE [Microgrid Systems](https://www.energy.gov/oe/microgrid-systems) | 発電・蓄電・需要を同じ境界で管理する局所電力系の説明 | 電力の単位・接続・運転費はゲーム用の尺度。月・火星で実証済みとは表示しない |

実験済みの要素と将来の一体運用を区別する。
これらからゲームの産出量・工期・価格を導いたとは扱わず、数値はGameContentの調整用仮値とする。
