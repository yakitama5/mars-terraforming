# 必ず子へ深まる研究

更新: 2026-10-20。横へ育つ木は本人から「いい感じ！」と評価された。
続けて、解放した研究と同じ階層へ別の研究が出る挙動を見直し、
新しい候補は常に解放元より深い子にしてほしいとの指示を受けた。

## 採用した発見順

以前は各分野の研究件数に応じ、実前提のない別の入口を増やしていた。
この件数条件を撤去し、初期4入口以外の33入口に明示的な「発見のきっかけ」を割り当てる。
例えば、水耕栽培から藻類の培養へ、その先に有機資源の処理へと枝を深める。
水の精製には採氷／加熱抽出のどちらからでも進める。

- 発見のきっかけはゲーム内の着想・用途のつながりとして扱う。
  カタログの科学的前提や、研究購入の実AND/OR条件へ追加しない。
- 新候補の発見は関連する研究の解放によってのみ進む。
  RP不足の予約が自動完了した場合も同じ規則を適用する。
- 配置、主枝・補助線、新候補へ寄るカメラには、実AND/ORと発見親の合併を共通利用する。
  候補だけを増やして同じ深さへ置くことを防ぎ、未知の親や将来の形を先に表示しない。
- 分野横断のE19はメカニクスM17とエネルギーE17の両方が実前提であり、
  エネルギー内でもE17より右の子になる。
- 研究RP費用、設備導入費、時間計算、報酬の数値は変更しない。
  発見時期と到達経路は仮調整であり、長期バランスの完成仕様にはしない。

## 保存の引き継ぎ

contentはdistrict-8へ更新し、schema 2を維持する。
`discoveredResearch`へ既知候補を保存し、研究済み・現在成立する候補・有効な予約と合併する。
配列は保存時に整列して、一括進行と途中保存で結果をそろえる。表示の読取りは状態を変更しない。

district-7以前では旧件数ルールの可視範囲を一度だけ復元する。
見えていた未購入・未予約の候補を消さず、それ以降の新発見には旧件数ルールを使わない。
人員、提携、世界ID、時計、RP、支払い済み研究、設備、受取済み報酬を保持する。
不正な既知研究の型・IDは元保存を上書きせず停止する。
現行版の手書き検証fixtureで新キーが欠ける場合は、新規則から可視範囲を導出する。

## 検証

- `mise exec -- bash tools/check.sh`成功。依存方向、98研究・全設備導入・保存再読込、
  100seedの時間分割、Python6件、整形、静的解析、Flutter **539テスト**を通過した。
- 追加19件で33入口の網羅と接続の無循環、4入口から全98研究への到達、
  20seed×98手の合法な解放順で可視範囲の単調性と実レイアウトの右方向成長を検証した。
  RP待ち予約の自動完成、OR両経路、別分野の最後の前提から発見するE19も含む。
- file/browserの旧v7保存、過去6版、繰返しロード、支払い済み工程の一度だけ完了、
  人員と提携の維持、不正保存の原本保全を確認した。
  既存検証の固定ドラッグ量はカード実位置への操作へ変更し、候補順と発見親のfixture2件を更新した。
- Web release成功。873×393と1280×800で未解放の世界を開き、
  **研究の解放は画面操作だけで**B01→B05と進めた。
  各段階で新候補全件が元技術より右、未知名・総件数の秘匿、既知の保持、
  同じworldIdと研究2件の再読込保持、pageerror 0、Chrome/contextの自然終了0を確認した。
  正規保存の検証fixtureはRP予算だけを増やしており、製品の初期残高とは異なる。
- 全16画像を目視した。全景表示は既知の範囲を収める明示操作として縮小するため、
  小画面では自然倍率の解放前後画像も併用する。自動表示の倍率下限0.85は維持する。

- iPhone 17 Pro / iOS26.1 Simulatorの通し試験が成功。
  研究から都市開発・輸送・居住編ED・人員と提携・保存再開まで通過し、
  画像2枚の回収、driver終了0、Simulator終了を確認した。
  初回Scene生成に最大4.3秒の停止警告が残った。実機性能の検証結果とは扱わない。
