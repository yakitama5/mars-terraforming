# 試作の決定と保留事項

2026-10-13。企画書 v0.4 全17章と今回の依頼を起点に実装。
企画書の2026-09-22時点の環境・進捗記録は、現在の実装状態を表さない。

## 確定方針を維持するもの

- 国家を持つ国際宇宙開発機関が、地球の産業を宇宙開発につなげる。
- Flutter + FlutterScene、iOS先行・Android後発、日本語・横画面。
- 全機能をオフラインで進行。端末時刻、端末内自動保存。Google連携は必須にしない。
- 開始・予約した作業だけ進む。未知の分岐を自動選択しない。
- 資金難から再建でき、強制ゲームオーバーはない。
- 閉鎖居住の実績と全球の居住可能化によるEDを別に扱う。
- 完成版の初回ED目標は現実4〜6週間。今回の短時間試作から到達保証はしない。
- 都市は六角区画を採用し、地形と隣接効果を重視する（今回のユーザー回答で確認）。
  区画数、地形配列、地区の種類・費用・効果量は調整対象。

## 現在の都市・研究の仮仕様

配置・研究・描画の正本は [戦略試作の記録](strategy-prototype.md)。
地球2都市・火星3都市、各25六角区画、9種類の地区、3段階増強、計10研究を実装。
新しい地区は工場／火星建設班で外部受注・自前製造と競合する。研究は技術前提と現地実証の両方で解放する。
メニュー・設定・オープニング・チュートリアルはゲーム部分の確定後に扱う。

## 導入工程と旧セーブに維持した数値

すべて仮値。定義は `lib/domain/game_content.dart`。通貨は架空の Cr。
期間は現実秒。別のゲーム内年代への換算はまだない。

| 項目 | 仮設定 |
| --- | --- |
| 初期資金・人口 | 900 Cr・120人、地球Lv.1 |
| 基礎税収 | 30 Cr/分。旧地区拡張は+18、新区画は地区・立地ごと |
| 維持費 | 研究所8・工場18・宇宙港14・火星建設班2 Cr/分 |
| 精密機器受注 | 工場90秒、開始40 Cr、完了220 Cr |
| 衛星打上げ受注 | 宇宙港120秒、開始80 Cr、完了360 Cr |
| 生命維持研究 | 研究所120秒、180 Cr、一度のみ |
| 居住キット | 工場180秒、260 Cr、研究完了が必要 |
| 地球→火星輸送 | 宇宙港180秒、220 Cr、地球キット1基消費 |
| 旧居住区建設（予約保持のみ） | 火星120秒、200 Cr、到着キット1基消費、12人居住 |
| 新しい火星居住地区 | 区画を指定、基本30分・700 Cr・キット1基、24人入居 |
| 旧地球地区拡張（予約保持のみ） | 工場120秒、300 Cr、人口+60人 |
| 新しい住宅地区 | 区画を指定、基本10分・350 Cr、人口+60人、維持費2 Cr/分 |
| 居住実績の報酬 | 方法別の初回のみ180 Cr、初着陸は報酬なし |

工程開始時に費用と貨物を確保し、完了時に成果を一度だけ反映する。
設備ごとに独立した予約順を持つ。同じ設備では受注と自前計画が競合し、
「設備・進行」の↑↓で次の予約順を変更できる。先頭が資金・前提研究・資材・分岐待ちなら、
その設備の後続も待つ。条件を満たす外部受注を前へ動かして、収入を先に得ることもできる。
別の設備は止めない。割合配分・支払済み工程への割込・途中払い戻しはまだない。

順番変更は、費用と貨物を確保済みの「現在の1回」を中断しない。その残り時間・貨物・
支払額を保持し、終了後の着手に新しい順番を適用する。実行中の計画に有限/無期限の反復が
残る場合は、将来の反復を「次の予約」にも表示し、他の予約の後ろへ移動できる。
無期限受注を終了させなくても、現在の受注1回→火星計画→受注の再開と配分できる。
未着手の計画が複数回反復する場合は、その予約順で指定回数を続ける（自動の交互実行ではない）。
現在の1回だけで終了する計画は、次の予約に表示しない。休止中も同じ規則で順番を編集できる。
移動は同じ設備の有効な次回予約間に限り、変更後は即時に自動保存する。
旧plans配列順を維持して保存形式2へ移行し、既存の支払済み工期も固定する。

有限反復は1回・3回、無期限は明示的な指定。通常の単発研究は二重予約不可。
待機予約の停止は取り消し、実行中の停止ボタンは支払済みの現在の1回で反復を終了する。
設備スイッチで実行途中を保留でき、再開後は残り時間から続く。
最大有効予約24件、終了履歴48件、画面用ログ40件。単調増加ID・累積受注収入・実績取得は削らない。

初輸送後にドーム/地下を選ぶ分岐を用意した。今回の保存枠では一度の選択で、
新しい地区ではドームは平地、地下居住はクレーターに税収の立地効果を持つ。
3Dは両方式とも共通の仮居住モジュールで表示する。
方式別の固有造形・リスク・研究ルートは今後相談する。閉鎖居住でEDは解除しない。
移住航路・継続補給は未実装。旧予約は12人、新しい居住地区は各レベルの完成時24人が入居する。

資金が尽きると宇宙港→工場→研究所→火星建設班の順で休止し、収支を非負にする。
税収は常に残る。再開は手動で、維持費1分分の資金が必要（追加の再開料金ではない）。
支援金の反復取得は未実装。住宅地区の拡張で税収を増やし、設備を再稼働できる。

## 時間と保存の実装判断

同時刻は収支積算→設備順の完了→資金難での休止→予約着手の順。
完了、資金枯渇、着手可能な資金額への到達を境界として進める。
毎秒で不在期間を走査しない。無期限反復は完了イベントごとに処理し、経過を切り捨てない。
内部通貨は1 Cr=60,000単位としてミリ秒単位の収支を整数で積算し、表示は小数切捨て。

端末時計と単調増加するシミュレーション時間を分離。時計が戻ったら経過0で基準を取り直す。
戻したあと時間が進めば新たな経過として進行する。罰則・ネット照合・時計の上限制約はない。
既に完了した仕事や実績は再実行しない。DEV_TOOLSの+5分／+1時間／+1日はシミュレーション時間だけ進め、
端末の基準時計は動かさない。開発モードは専用 development 保存枠を使う。

起動・復帰・重要操作後と前面稼働中5秒ごとに、状態・時刻・取得記録を一世代で保存。
ゲーム進行は保存形式2・コンテンツdistrict-2。保存コンテナは従来の形式1。
SHA-256付きJSON、正常な前世代1つを保持。
一時ファイルをflushして同じディレクトリ内でrenameする。未確定pendingは採用しない。
破損時は前の正常世代へ回復。未知形式や正常世代なしの場合は新規ゲームで上書きしない。
形式1・prototype-1から人口・研究・報酬・予約・残時間を保って移行する。旧世界は区画外の既存市街として保持。
プロセス終了を対象とし、電源断時のdirectory fsyncによる耐久性は未保証。

## Web試遊の位置づけ

ユーザーの追加依頼により、このPCで操作できるWeb版を追加する。
iOS先行・Android後発という配信方針は維持し、Webは現在の試作を触るための経路とする。
ゲームとFlutterSceneは共通。WebGL2で描画し、ブラウザ保存だけを条件付き実装で差し替える。
Webの2世代保存は1キーへ一括確定し、Web Locksで同時タブの進行を防ぐ。
キャッシュ取得後は通信なしで再読み込み・進行できる。同梱フォント・描画資材もCDN不要。
保存はブラウザ/origin/通常・開発枠ごと。ネイティブ版との同期・Googleバックアップは未実装。
設定と制限は `web-preview.md`。Web追加で費用や工程時間は変更していない。

## 画面・描画

「惑星マップ／都市開発／研究ツリー／設備・進行」の4つを主タブとする。
惑星はFlutterSceneで球体を描画し、複数都市を選択できる。都市内は六角区画と見積もりを並べる。
研究は前提関係の線と3系統の技術を表示し、全体表示・等倍・拡大縮小で見渡せる。
都市・研究の予約ボタンを下へ固定し、小さい横画面でも操作の入口を見失わないようにする。
設備一覧はPCで2列、小さい横画面で1列。現在の1回と次の予約を分け、進捗・対象区画・停止理由を表示する。
↑↓で順番変更、停止アイコンで取消/反復終了、スイッチで設備休止/再開。
地区の効果と維持費も対応設備の休止に連動する。
すべてローカルの基本形状。球面上の街は地区の総レベルに応じた模式表現で、実際の区画を縮尺どおりに描かない。
コンセプトアートはリポジトリ内で見つからなかった。最終の絵柄・配置・UIは未確定。
政策操作・税率変更・住民AIは未実装。

## GitHub Pages運用（採用・公開済み）

mainを確認済み通常版、developを時間送り付きの試遊版とする。
作業ブランチ→develop→mainをPRで反映する。1つのPagesサイト内でパスを分け、
両先頭SHAの成果物をまとめて配信する。
保存・ロックはリポジトリ/環境の名前空間、キャッシュは配信パスで分離。
配信方式とゲームの仮値は分離し、ルールの更新は戦略試作の記録に残す。
ユーザーがPublic化済み。main/develop作成、意味のある粒度での初回コミット・push、
両方のPages配信を承認済み。初回pushと両方の実配信・Chrome検証まで完了。
最新の配信対象SHAはdeployment.json、初回コミット分割と再現手順は `github-pages.md`。
