# 共通RPと育つ研究ツリーの実装

更新: 2026-10-20。Dear Mars の研究・都市設備を対象とする。
[研究候補](research-tree-catalog.md)・[解放先の企画](research-unlocks.md)を起点にした実装記録。
当日の「まだ実装しない」という指示は、続くユーザーの実装・main反映・内部テスト配信の依頼で更新された。

## 今回の依頼と実装範囲

- 4分野をバイオ／メカニクス／マテリアル／エネルギーと表示し、都市の施設と研究者から共通RPを生産する。
- RPと研究前提が揃えば確実に技術を解放。新しい研究へ従来の資金支払い・追加待機を重ねない。
- 99候補のうちE06の変換機をE05の小型核分裂電源一式へ統合し、購入可能な技術は98件。
- 各技術から施設・機体・設備・製法・運用の導入計画を解放。知識の取得と導入・稼働は別の投資にする。
- 最初は4分野それぞれの入口だけを発見。解放に伴い次の候補と別の枝の入口が見つかる。
- 未発見の技術名、ノード、接続線、総本数、将来の配置範囲は画面・Semanticsへ出さない。
- 分類別の生成画像4枚、技術カード、有限の枝の伸長・カード出現・解放光輪・粒子・視点移動を追加。
  短縮モーションに対応し、保存済みの解放は読み直しても一斉再生しない。
- 案内・Tips・人員配分・資源説明もRP方式へ更新する。
  初回の研究前後2段階は旧方式の録音を誤再生しない字幕案内に更新し、他の既存音声は維持する。

## 研究と設備の進行

RPは固定小数点（1RP = 6,000,000単位）で積算する。
時間・資金枯渇・予約が必要RPへ到達する境界を進行エンジンで処理し、画面で進行計算を複製しない。

研究は即時解放、または順番とRPを待つ予約を選べる。予約していない枝を自動で選ばない。
初期研究所で全分野に使えるRPを生産でき、専門設備の建設前から研究を進められる。
通常の停止・費用説明・安全な優先配分を先端研究の購入条件にしない。

技術の導入計画は、対応する開設済み都市を選び、共用の工場・宇宙港・研究所・火星建設班へ予約する。
完成した設備は最初は休止し、プレイヤーが稼働と配属を決める。
人員・維持費・設備の稼働条件を満たして初めて効果が出る。
設備に配属する研究者は研究部門の総数の内数、設備運用の工業員は工業部門の内数とし、
同じ人を基礎研究所、専門設備、支払済み工程へ重複配置しない。

生産系施設の実験運転に人を回すと生産への寄与が下がる。
空の専門研究設備はRPや研究の相乗効果を生まない。
稼働設備の外部受注・対応する貨物便も、既存の製造・輸送枠を使う。
共同設備には既存提携の条件を付ける。収入・RP・製造・輸送・建設の役割を分け、
設備ごとの具体的な維持費と効果は導入画面に表示する。

一般の住宅・受注・最初の貨物輸送を残し、全研究・月経由・核熱推進の取得を初居住の条件にしない。
既存の居住方式・居住編ED・報酬条件を変更していない。
大型機と小型機、再使用と整備、輸入と現地製造の比較は、既存の資材・能力へ集約した試作である。

## 保存と移行

schema 2を維持し、contentをdistrict-7へ更新。
旧19研究IDはカタログ内で再利用する。
district-6以前の研究解放、支払済み工程の残時間・確保人員、都市、予約、通知、提携を保持する。
新規RP研究に移行した後も、更新前に支払った実行中研究は元の工程を最後まで進め、
RPや資金をもう一度徴収しない。通常の旧世界へ過去分のRP・設備・報酬は付与しない。

例外は、旧版の保護された初回案内中に最初の研究へ未着手でRPがまだ存在しない保存だけ。
時計停止とRP不足が循環しないよう、最初の研究に必要な初期研究予算を一度引き継ぐ。
RP項目を保存した後、通常世界、研究済み、支払済み工程には繰り返し付与しない。

## 検証

ローカルで確認したこと:

- 採用Flutter 3.47.7 / Dart 3.13.5と固定された依存を維持。オフラインのlockfile付き依存解決に成功。
- 静的解析成功、依存方向の検査成功、モバイルCDのPython回帰6件成功。
- Web releaseビルド成功。iOS/Androidのビルド・署名は既存の固定構成を引き継ぎ、CIで確認する。
- tools/verify_research.dart が98研究の解放・全設備の対応都市への導入・保存再読込、
  100seedの一括／分割進行、RP待ち、資金休止、人員制約、旧工程・途中案内移行を検証して成功。
- 初期資金と公開コマンドだけの一経路で、受注・研究・建設・輸送・初居住・保存再読込まで
  1,471秒の机上試走に成功。最短解・通常時間の試遊・全球クリアの達成保証ではない。
- tools/verify_progression.dartで、資金・RP・設備を注入しない選択居住経路を再試算。
  通常25研究で11.945日、任意の先端研究6件を含む36研究で13.605日となり、
  どちらも2都市・居住棟2件・火星人口48人へ到達した。全98研究や全球クリアの試走ではない。
- 同じ60分の公開操作比較で、貨物優先は初配送15分／初居住25分、基準経路は47分／56.52分。
  工業優先と住宅優先は工業完成52.23分／57.52分、住宅Lv2完成55.86分／44.69分となり、
  資金を稼ぐ設備と人口を先行させる選択の違いが残る。
- 提携の資金方針／技術方針は両方とも60分で研究者10人・工業員8人、6地区・火星人口24人。
  最大判断間隔は各5.9分、実際の開発完了の最大間隔は6.06分／8.07分。
  先端研究24,000RPと第2居住棟はこの60分では未完成とし、試算結果へ区別して記録する。
- tools/verify_investments.dartの、成長都市／密集都市それぞれ7単独投資と2件の3施設投資について、
  見積もり・実現値・保存再読込の比較が成功。

既存domainテスト6ファイル63件、および予測・地区・表示秘匿の追加検証は、
純Dart上で標準Matcherを使った同期本体の補助実行にも成功した。
正式なFlutter runnerによる全体検証とは分けて扱う。

ローカルのFlutter Widgetテストはテスト用localhostソケットをOSに拒否され、ロード前に停止した。
製品のテスト失敗と区別し、GitHub CIで全テスト・実画面PNG・モバイルビルドを実行して確認する。
bash tools/check.shは実行済み。依存方向・98研究の直接検証・Python6件・全134ファイルの整形確認が成功。
統合作業中に検出したlintを修正し、既存テストの新方式への適応後にCIで全工程を再検証する。

CI・実画面レビュー・main反映・内部配信の最終結果は作業完了時に本節へ追記する。

## 制約と次の判断

数値はGameContentへ集約した調整用の仮値。4〜6週間の全球クリアや累計操作20時間は未検証。
98の固有資源在庫や化学・軌道力学の詳細シミュレーションは導入せず、既存の資材・能力へ集約している。
現時点の設備は都市へ帰属する主要設備で、六角地図の既存地区と別の導入一覧で運営する。

月専用M13/M16/M19/E03/E20/E24は、地上の準備・実証モジュールとして導入する。
月面都市・月の補給網が既に稼働したとは表示しない。
R24等も試験設備までで、惑星全球の環境効果やED条件を成立した扱いにしない。
全球判定、火星復元、周回継承、収益化の未決定ルールは今回の実装対象外。

次は内部テストで、RPの貯まる速度、施設の維持と人員配分、分岐発見の頻度、
小さい横画面でのカード・アニメーションの読みやすさを評価する。
