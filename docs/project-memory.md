## 今回確認できた見た目の方向

円形の地盤と川を追加した箱庭に、ユーザーから「いい感じ！」という評価を得た。
**円形に切り出した土地に街と自然が収まる構図を、次の改善の基準とする。**
見た目の細部・操作・全ゲーム仕様まで完成承認されたとは扱わない。

- 惑星を選ぶ画面は球体。都市開発は、瓶に収めた小世界のような円形の箱庭。
- 地盤の厚みと土の断面、川・岸・橋・丘が読み取れることを重視する。
- 都市の初期表示は箱庭の全景。「市街」で選択区画へ寄り、「全域」で戻る。
- 施設を選び、実際の地形上の六角タイルを選び、費用・工期・隣接効果を見て予約する。
  工事・完成・増強は同じ場所のモデルへ反映する。独立した六角の盤面へ戻さない。
- 信長の野望やCivilizationを参考に、地図が主役のゲーム画面と分かりやすい国力の数値を目指す。
  モバイルアプリのカード一覧が主体になる構成は避ける。
- 建物の用途・街路・素材・影・街の密度で成長を見せる。参考画像のアセットは使用しない。
- 透明な瓶の壁や屈折は未実装で、必須仕様として合意したものでもない。
  川や橋は現在は景観。水運や河川ボーナスは実装していない。

基準にする実画面: [Web全景](screenshots/terrarium-web-whole.png)、
[施設配置](screenshots/terrarium-web-placement.png)、[iOS全景](screenshots/terrarium-ios-whole.png)。
具体的な形状・色・密度・川幅・カメラ値は [円形の箱庭](circular-terrarium.md) の仮設定。

## ゲーム体験と時間の目標

- 国家を運営する国際宇宙開発機関として、地球の街と産業を研究・製造・輸送・火星開発につなげる。
- 外部受注の収入と自分の開発が同じ設備を取り合う判断を中心にする。
  既存都市の増強か新都市への展開かを、費用だけでなく期間・土地・隣接効果で悩めるようにする。
- 最初の建設は約5分。**最初の約1時間はチュートリアル込みで遊び続けられる状態を目指し、その後に徐々に放置へ移る**。
  研究・都市配置・設備の順序・人員・提携を並行して考える。待ち時間だけを延ばして長期化しない。
- 初回EDは現実4〜6週間、1ルートの実操作・計画は累計約20時間を目標とする。
  オフライン待機は20時間に含めない。以前の50時間案は更新済み。いずれも調整目標であり、達成確認は未完了。
- 通貨表示はドル。旧Crと数値は同じで換算しない。実際の宇宙開発費ではなくゲーム用の仮値。
  人口と専門職は分け、資金・税収・維持費・技術力・知名度・研究者・工業員・友好度・宇宙支援貢献を理解できる表示にする。
- 提携と支援は初期実装済み。友好度は協力先全体の単一指標で、国別外交や豊富な動的イベントは未実装。

序盤の最新試走は [並行開発と機関運営](agency-development.md) を参照。
2経路の最大判断間隔は各5.50分、意味のある開発完了の最大間隔は5.50分／8.94分。
以前の約13分の空白への改善はあるが、1時間ずっと面白く遊べることや20時間の内容量の証明ではない。

## 維持する基盤と保留事項

- Flutter + FlutterScene、日本語・横画面、iOS先行・Android後発。WebはPCから試遊する経路。
- 完全オフライン、端末内自動保存、端末時刻を使用。時計変更を罰しない。Google連携は任意で後段。
- 開始・予約済みの作業だけが進む。指定回数／無期限反復と、未選択の分岐での停止を維持する。
  順序変更は支払済みの現在の1回を中断せず、次の着手から適用する。
- 資金難から再建でき、強制ゲームオーバーは設けない。研究は実証・構想・SF上の仮定を区別する。
- 居住方法別の実績と、全球屋外居住のメインEDを分ける。ED後の続行・研究継承の周回は後段。
- メニュー・設定・オープニングはゲーム部分が固まってから。現在の状態別行動案内は維持する。
- 火星復元の基本方針は、指定時点の環境・施設・住民へ戻し、資金・地球施設・研究成果・解除済み実績を保持。
  固定待機中は火星が停止し、次の計画だけ編集可能。地球・月は進行し、同じ報酬は再取得不可。
- 復元時の在庫・輸出済み資源・売却施設・移住者・輸送・二重取得防止の詳細と待機日数、
  全球居住の具体的条件、周回時の途中研究・実証データの継承範囲、収益化は着手前に相談する。
  これらの未決定を理由に序盤の改善を止めない。

## 実装・検証の現在地

- 地球2都市・火星3都市、各25区画、9種類の地区、Lv.3までの増強、13研究。
  数値の定義は `lib/domain/game_content.dart`。進行・保存・UI・描画の責務分離を維持する。
- 採用版は Flutter 3.47.7 / Dart 3.13.5 / FlutterScene 0.24.3。
  これは採用記録であり、今後の最新版を保証しない。SDKと依存はmise・pubspec・lockfileで再現する。
- 保存形式2 / content district-5。今回の景観変更では費用・工期・ID・隣接計算・保存形式を変更していない。
- 2026-10-15の景観実装の検証: 221テスト、依存方向・整形・静的解析、Web release、
  Chrome実操作、iPhone 17 Pro / iOS 26.1 SimulatorのGPU描画と操作、公開main/developの操作が成功。
  Webの検証NodeとiOSドライバは手動終了せず完走した。
- 未実施: iOS実機・Androidの性能／電池／長時間GPUメモリ、Safari/Firefox。
  旧キャッシュから新Service Workerへ切り替わる更新過程も未検証。
  iOS初回シェーダー生成には最大約0.61秒の停止警告が残る。
  数値試走・時間加速・今回の見た目の評価を、長期バランスの達成確認へ置き換えない。

## 開発の進め方と再開時の入口

- 実装→自動検証→実画面で比較→改善を繰り返す。節目では操作手順か実スクリーンショットを共有する。
  実施・未実施の検証、仮値、残る問題を区別し、細かな仮値のたびに相談して止めない。
- 未コミット変更を尊重し、意味のある粒度でコミット。作業ブランチ→develop→mainをPRで反映する。
  mainは通常版、developは時間送り付き版。保存・ロック・キャッシュを分ける。
- [通常版](https://yakitama5.github.io/mars-terraforming/) /
  [開発版](https://yakitama5.github.io/mars-terraforming/develop/)。両ブランチのpushで両方をまとめて自動配信する。
  直近の実配信は [PR #17](https://github.com/yakitama5/mars-terraforming/pull/17)。
  配信の現在値は [deployment.json](https://yakitama5.github.io/mars-terraforming/deployment.json) で確認する。
- 実フォルダ名は `mars_terraforming`、GitHub名は `mars-terraforming`。
  検証は `mise exec -- bash tools/check.sh`。Web/iOSの詳しい再現方法は [開発手順](development.md) と [Web検証ガイド](web-preview.md)。
  Flutterのtest/build/driveは同じcheckoutで並列実行しない。検証は専用セーブを使う。
- 次の改善候補は、採用した箱庭での街の成長と用途の読みやすさ、序盤の判断密度、
  既存都市と新都市の投資比較、実機性能。優先順位は次のユーザー指示に合わせる。
