# 序盤の並行開発と機関運営

2026-10-14 / content `district-5`。初期段階の仮仕様。独立したメニュー・オープニングは後回しにする。

## 今回の狙い

最初の建設を約5分から始め、最初の1時間は研究・都市配置・設備の順序・人員・提携を
考えながら進め、その後は予約して離席する遊びへ移る。1ルートの目標は累計約20時間の
操作・計画と、現実4〜6週間の初回プレイ期間。オフライン待ち時間は20時間に含めない。
数値シミュレーションは待ち時間を確認するためのもので、遊びの密度や楽しさを証明しない。

前段district-4の共通経路では、37.3分の発電完成から工業完成まで約13.54分空いていた。
この間にも研究所を使い、どの設備の効率を先に育てるか、資金を今受け取るか技術へ投資するかを選ぶ。
新しい作業を勝手に始めず、操作・予約した仕事だけを進める。

## 数値の読み方と仮ルール

- 資金はドル表記に統一する。旧1 Crを1ドルとして表示名だけを変更し、換算・切上げ・資産再評価は行わない。
  金額・税収・維持費はゲーム用の縮尺であり、実際の宇宙開発費の見積もりではない。
- 知名度、技術力、外国との友好度、宇宙支援の貢献度を機関運営に表示する。
  都市の人口と、機関が抱える専門職の人数は別の指標として扱う。
- 専門職は初期12人、研究者6人・工業員6人。各6人を基準に1人あたり効率±2ポイント。
  施設・研究・提携と同じ効率上限を使い、初期配分なら従来の工期が変わらない。
- 研究者と工業員の配分を変更できる。進行中の研究・工場作業に確保された人数は完了まで減らせない。
  設備を休止しても確保は解除しない。支払済み作業の費用・工期は途中変更しない。
  無期限受注では次の1回も人数を確保する。減員するには反復を終了し、現在の1回を完了させてから配分を変える。
- 専門職育成は研究所を使い、基礎3分・600ドルで2人、合計36人まで。研究との設備の取り合いになる。
  増えた人は工業へ配属し、その後に配分を選ぶ。専門職の給与は試作では既存の設備維持費に含める。
- 架空の企業・国際共同体から届く提携・支援を、条件を満たした時点で提示する。
  一度だけ選択でき、選択しなくても時間・ほかの設備は止まらない。自動選択や期限切れはない。
  将来を試算する「予約の見通し」でも選択しない。

指標の仮計算は以下のとおり。各指標の上限は100点。反復受注の回数では増えない。

| 指標 | 計算・意味 | 今回の用途 |
| --- | --- | --- |
| 知名度 | 研究数×4＋完成区画数×2＋実績数×8＋協定数×3 | 都市技術の共同研究は6点以上 |
| 技術力 | 研究数×6＋地区の総レベル | 都市技術6点、工業提携12点以上 |
| 友好度 | 初期10点＋協定で得た点 | 宇宙支援は13点以上 |
| 宇宙支援貢献 | 輸送/居住系研究数×3＋実績数×8＋火星総レベル×2＋協定の点 | 宇宙支援は11点以上 |

解禁には点数だけでなく、都市基盤・完成地区・工業地区・初着陸などの実証も必要。
友好度は今回、協力先全体の指標として扱う。国ごとの関係図や外交交渉はまだない。
点数そのものによる自動収益・割引はなく、実際の効果は選んだ協定と研究に紐づく。

| 提案 | 継続的な技術提携 | 一度の資金支援 |
| --- | --- | --- |
| 都市技術の共同研究 | 研究+4、製造+2ポイント | 1,200ドル |
| 工業設備の共同開発 | 製造+6ポイント | 1,800ドル |
| 火星輸送への国際支援 | 研究+4、輸送+4ポイント | 2,400ドル |

協定は各提案1択。効率は設備の上限内で次の着工から反映する。
相手は架空の組織で、実在国・企業からの協賛や科学的承認を示すものではない。

## 短い研究を選ぶ

| 研究 | 基礎費用 | 基礎工期 | ゲーム内の効果 |
| --- | ---: | ---: | --- |
| 工程設計 | 200ドル | 3分 | 製造効率+3ポイント |
| 輸送梱包 | 300ドル | 4分 | 輸送効率+3ポイント |
| 居住運用 | 450ドル | 5分 | 火星建設効率+3ポイント |

都市基盤研究から分岐する。居住運用は生命維持も必要。
どれも既存3系統の任意の応用研究で、先の技術へ進む必須条件を増やすものではない。
工期・割合は調整用の仮定。実際の科学的実証からこれらの数値が得られるとは主張しない。
従来の生命維持の資料・実証と火星への応用の区別は維持する。

## 参考にした設計の考え方

[信長の野望・新生の政策マニュアル](https://www.gamecity.ne.jp/manual/shinsei/jp/8100.html)では、
金銭だけでなく人材・威信・準備期間・維持費が政策の条件と効果につながる。
[Civilization VII公式初心者ガイド](https://civilization.2k.com/fr-FR/civ-vii/news/civilization-vii-beginners-guide/)では、
食料・生産・科学などの出力と外交のための影響力を段階的に扱う。
今回は「何を増やすと、どの選択肢や作業に効くか」を画面内で説明する構成を参考にした。
他作品の数値・技術ツリー・固有の表現を複製してはいない。

## 保存と検証

旧district-4の実エンジン `f385948` から生成した `test/fixtures/district_v4.json` を使う。
研究と受注を開始して30秒経過した実保存で、研究の残り90秒/支払済み120秒、
工場の残り60秒/支払済み90秒を含む。移行後も費用・残時間を維持する。
専門職・配分・確保人数・提携選択と受取済み報酬を同じ保存世代に記録する。

### 序盤60分の試走

`dart run tools/verify_progression.dart` の `parallelStrategy` は初期900ドルから
公開コマンドだけで進める。初期資金の注入・完了状態の偽装は行わない。
単純な受注の自動反復は判断にも開発完了にも数えない。

| 60分の到達点 | 資金支援を選ぶ | 技術提携を選ぶ |
| --- | ---: | ---: |
| 最大の判断間隔 | 5.50分 | 5.50分 |
| 判断が起きた異なる時点 | 18 | 17 |
| 意味のある開発完了の最大間隔 | 5.50分 | 8.94分 |
| 残金 | 5,151ドル | 1,184ドル |
| 完成地区 / 総Lv | 6 / 7 | 5 / 6 |
| 住宅Lv | 2 | 2 |
| 専門職 / 研究者 / 工業員 | 16 / 8 / 8人 | 16 / 8 / 8人 |
| 定常収支（税収−維持費） | +37ドル/分 | +42ドル/分 |
| 研究効率 | +13% | +21% |
| 製造効率 | +13% | +9% |
| 輸送効率 | +3% | +7% |
| 火星の居住者 | 24人 | 24人 |

両方で短い応用研究3本・2回の育成を終え、第2の火星地区を施工中。
資金側は工業地区を完成し3件の支援を受け、技術側は2件の協定を選び工業を施工中。
研究や製造の効率差には、その時点の地区・人員・研究・協定をすべて含む。
同じ完成状態ではないため、この表だけで長期の最適解を決めない。

技術側も同じ投資順を強制すると資金繰りが悪く、最大判断間隔は約13.59分残った。
住宅増強を先に進め、研究費に応じて短い研究と育成の順を変え、工業の着手費用が
貯まるまで受注を先頭に残すと5.50分へ縮まる。育成費600ドルの値下げは採用していない。
画面でも、資金不足の建設を先頭へ置くと後続の受注も止まることを案内する。

判断間隔は「その時点で実際に新しい研究・配置・予約順・人員・協定を選んだ間隔」。
完成するまで操作が不要な区間と区別する。全技術経路の完了間隔8.94分が消えたとは主張しない。
これらはスクリプトによる選択機会の実測であり、初見の人が1時間退屈せず遊べたという検証ではない。
新しい全13研究・火星2都市の長期経路は約9.122日で到達。全球EDは未実装で、
20時間の能動プレイや4〜6週間の初回ED目標の達成を示さない。

### 実操作・公開検証

- `bash tools/check.sh`: 依存方向・47ファイル整形・静的解析、全173テストが成功。
  時計の前後退、保存/再開、有限/無期限育成、人数上限、資金/人員不足、paid人員拘束、
  支援二重付与防止、予測が支援を自動選択しないこと、一括/分割進行、v4両保存移行を含む。
- Chrome Web release: 1440×1000と844×390で実操作。
  応用研究と受注の並行、配分5/7へ変更、提携の選択、専門職14人への育成、
  保存再開・2タブ排他・オフライン再読み込み・予約見通し・投資比較を通して成功。
  外部originへの資材要求なし。context/browserを閉じたあと、Nodeが手動終了なしで終了コード0。
- iPhone17 Pro / iOS26.1 Simulator: Xcode build 32.3秒、実GPUを使うdriveテスト61秒で成功。
  人員5/7への変更、支援選択、14人への育成、保存再開、既存の球体・研究・区画建設・
  比較と見通しを確認。テスト用の一時セーブだけを使用し、終了後は端末データを消さず停止。
  初回Scene描画で最大約1.4秒のpipeline生成ログあり。実機の描画負荷は未測定。
- Webで人員Sliderの空の全面semantics要素が操作を遮ることを再現。
  別行配置や値表示の無効化では解消しなかったため、人数テキストと±操作に整理した。
  強制クリックやDOMの検証専用書き換えは使わず、通常クリックで再確認した。
- 案内の三角文字 `▾` が同梱フォントに含まれず、外部フォント要求の検査に失敗。
  同梱フォントで描ける `▼` へ変更し、全Web操作と外部要求なしを再検証した。
