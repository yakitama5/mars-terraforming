## 1. 今回のユーザー方針と、この案の位置付け

今回のユーザー意向:

- 研究で解放された施設を都市開発の地図に建てたい。
- 能力補正に加えて、見た目・役割に違いを出したい。
- Civilizationのように多種多様な建物と効果を持たせたい。
- 都市開発→技術研究→次の惑星への循環を軸に、新施設・新効果を継続追加できる構造にしたい。
- 今回はまず拡張案を検討する。アプリの実装・配信は依頼されていない。

上記を今回の設計方向として記録する。
**以下の区画構造、32候補、優先12系統、資源分類、効果、導入順は提案であり、採用済み仕様ではない。**
価格・工期・産出量・必要人数は今回確定しない。既存施設の再編を含み、32施設を新規追加する約束ではない。

## 3. おすすめする都市と施設の構造

### 25区画を残し、小さな施設の併設と大型施設の専有を組み合わせる

通常区画は**主要な建物を2棟まで**配置できる案を推奨する。
2棟はスマートフォンで外形を読み分けるための比較用の上限で、画面試作後に調整する。
宇宙港、宇宙エレベーター、大型ドーム、大規模採掘設備などは1区画を専有する。
すべてを2棟詰める前提にはせず、土地・電源・担当者によって都市の性格が変わるようにする。

- 施設を選び、地図の区画へ寄り、区画内の建設位置を選ぶ。完成後もその建物を直接選べる。
- 新しい通常施設のために、空の「研究地区」を先に買う二重の建設手順は増やさない。
  用地整備が必要なら同じ見積もりに含める。
- 既存の研究・工業地区は共用設備を持つまとまりとして生かす。既存の住宅の棟群も残す。
  住宅の人口や工場の仕事を、小さな追加施設の設置で無断に置き換えない。
- 枠の案では、基礎研究所・通常工場などの主施設も2棟のうち1棟に数える。
  複数の装飾棟が見えても一つの施設資産とし、地区基盤の能力を別に重ねて付与しない。
  住宅棟群は専有区画として維持する案から比較する。既存地区との最終対応は画面試作で確認する。
- 同じ研究地区でも、分析所＋現地ラボと、温室実験棟＋培養棟で形と仕事が変わる。
- 付属設備は屋根、側面、庭、搬入口などの取付位置に増設する。小さな装置ごとに土地を1区画使わない。
- 大型機・ローバーは所属する格納庫や整備場に現れる。出発中はその機体が不在になる。
- 軌道組立拠点・軌道デポは地表に建てたように描かず、地上の管制・搬出入施設と軌道側の実体を関連付ける。
  軌道専用の地図は後続案とし、先に必須画面を増やさない。

1区画1施設だけの方式は分かりやすいが、25区画を早く使い切る。
地区内の一覧だけで施設を増やす方式は、今回求められた地図で建てる実感が弱い。
併設案では、**プレイヤーが場所を選び、固有の建物がそこへ残ること**を条件にする。

土地を無限に増やす案は採らず、まず既存都市間の分業を使う。
将来の周辺開発・新都市は、新しい立地の選択が必要になった段階で比較する。
すべての施設を一都市にそろえることを目標にしない。

通常プレイで土地が埋まったときには、再配置・建て替えによって用途を組み替えられる案を推奨する。
工事前に失う産出と移す作業を確認し、保存した資産・工程を消さないことを条件にする。
移した施設の効果を旧位置へ残したまま、新位置にも付けることはできない。
移設費・工期・取り外した設備の保管は数値設計時に比較する。
主要な進行には輸入・基本設備・別都市も利用できる入口を残す。
これは満杯の一都市へ任意施設を何棟でも追加できる保証とは分ける。

### 研究の解放先を4通りで地図につなぐ

| 解放するもの | プレイヤーの操作 | 地図に出る変化 |
| --- | --- | --- |
| 建物 | 用地を選んで建設 | 固有の輪郭、搬入口、仕事と担当者を持つ建物が増える |
| 設備・製法 | 対応建物を選んで増築・製造方式を設定 | 回収槽、パネル、配管、別棟、積み荷が変わる |
| 機体 | 工場で製造し、対応する基地へ配備 | 格納・整備・出発・帰還が建物と対応する |
| 運用 | 対象施設と航路・作業枠・配分を選ぶ | 補給先・稼働対象・扱う貨物が変わる |

研究完了は設計の解放。建物・機体・収入・人員の無償付与とは分ける。

## 4. 施設ごとに「できること」を変える

新施設には、次の作用のうち少なくとも1つを持たせる。
既存の効率補正は補助として使えるが、それだけで独立した建物を増やさない。

| 作用 | プレイ上の違いの例 |
| --- | --- |
| 作れる物・受けられる仕事 | 食品検査棟で品質指定の受注、造形工房で対応する交換部品を製造 |
| 原料を別の物へ変える | 採氷→用途に合う水→水電解。必要な設備と電力を選ぶ |
| 作業の並列数・占有 | 整備場は機体を再使用可能にするが、整備中は機体と担当者を使う |
| 供給先・接続 | 配電センターで複数施設を結び、発電向きの土地と工業用地を分ける |
| 貯蔵・備蓄 | 蓄電や低温貯蔵に投資し、次の実験・便の準備をためておく |
| 土地の情報・用途 | 分析所で採掘候補を比較し、適した工場と都市を選ぶ |
| 生産と研究の切替 | 温室や材料工場の一部を実験へ回すと、生産を減らして共通RPを得る |
| 特別な計画 | 大型組立棟で大きな積み荷、乗員準備棟で有人運航の準備へ進む |

設備を増やすと維持費・人員・電力・用地のいずれかが必要になる。
安価な輸入と小規模設備、高い初期投資と現地生産を比較できるようにする。
高価な新施設が、低頻度の小規模運用でも必ず最善になる構造は避ける。
資源分析所がなくても基本の地形・費用・配置条件は確認できる。
新しい分析で見られるのは、試料に基づく詳細な適性や工程の比較とする。

### 物流と電力は、理解できる規模から始める

供給の表示は当初、補給品・水系・部材・推進剤の4系統程度を上限目安とする案。
これは新しい4通貨ではなく、何を生産し、何を輸入し、何を消費するかを見るための分類。
食品と薬、用途別の水、酸素と燃料、月面用と火星用の対応推進剤は、製品・適合条件を区別する。
同じ分類だから相互に無条件変換できるとは扱わない。
研究ごとに独自の化学物質在庫を増やさず、具体的な製品が判断に必要な部分だけ個別化する。
分類を4系統に収めても、製品在庫や接続設定が増えすぎると管理は重くなる。
初回は一つの連携につき少数の入力・出力から始め、個別在庫・接続・運転設定の数も同時に評価する。

電力は供給力・設備の需要・工程中の追加需要・蓄電残量を見せる案とする。
蓄電池は発電せず、充電した分だけ工程の需要を補う。
日照や月の長い夜を精密再現するために、初期版から新しい暦や周期を必須にしない。
不足時は該当する新規工程を待機させ、理由と解消方法を示す。
生活設備の突然の破壊や、留守中の連鎖的な損失を新設しない。

これらの供給量・在庫・電力モデルは**現行実装への追加案**で、既に存在する機能ではない。
最初の改修で全体系を同時導入せず、必要な施設の組み合わせから段階的に検証する。

### 改修にも外観と使い道を持たせる

- B02/B11: 温室へ噴霧装置・回収槽を増設し、補給する水や運転負担の違いを選ぶ。
- B12: 稼働している温室・処理棟・培養棟を接続する。対象のない循環ハブ単体では利益を生まない。
- R16: 造形工房へ回収ラインを足す。供給した廃材を超える原料は生まない。
- R17/R20: 盛土と防護パネルで居住棟の姿を変える。立地・搬入・材料で使い分ける。
- E04: 太陽光設備へ清掃装置を追加。通常の清掃運用と投資を比較する。
- E21/E23: 断熱材や展開放熱器が外観へ付く。対象建物の熱管理に役割を限定する。

## 6. 都市→研究→次の惑星を、同じ作業の繰り返しにしない

基本の循環:

1. 街の収入・人員・基礎研究から、共通RPと次の投資余力を作る。
2. 目的に合う研究を選び、新しい建物・改修・機体を解放する。
3. 地図で立地と組み合わせを選び、建設・配属・稼働へ投資する。
4. 新しい製品・受注・調査・輸送が可能になり、街の役割が変わる。
5. 蓄えた能力で次の天体へ進み、前の街と現地のどちらへ投資するかを選ぶ。

| 段階 | 新しく考えること | 前の都市が引き続き担うもの |
| --- | --- | --- |
| 地球で産業を育てる | 収益事業・研究・機体製造へ人員と土地を配分 | 資金、共通RP、完成機材、最初の輸送 |
| 初打ち上げから月面拠点へ | 限られた便で運ぶ設備を選び、基地と打ち上げ基地を建てる | 補給品・機材の生産、輸入で動く入口を支える |
| 月を補給・試験拠点に育てる | 採氷・電源・貯蔵・シャトルへどこまで先行投資するか | 精密部品・人員・大型設備の供給 |
| 火星探査から居住へ | 現地の水・大気・土地を生かす産業と、輸入継続を比較 | 地球と月の供給網、追加研究、輸送 |
| 火星の都市を分業させる | 居住・食品・材料・研究の特化と接続を選ぶ | 以前の施設を改修して、新しい需要へ対応 |

初打ち上げ→月→月面基地・打ち上げ基地→火星探査という採用済みの順番は維持する。
採氷・燃料工場・エレベーターなどの全取得を、火星へ行く追加必須条件にはしない。
初期の小拠点は輸入・基本キットで成立し、便数・人口・現地需要が増えたときに自前設備が魅力になる設計を推奨する。

### 進め方が変わる3例

- **輸送を早く広げる街**: 地球の受注と宇宙港を優先し、初便は輸入機材で進む。
  便数が増えたら回収・再整備へ投資する。最初から全燃料製造施設はそろえない。
- **研究と高付加価値事業の街**: 温室・検査棟・医薬試作へ配分し、収益運転と実験を切り替える。
  研究で輸送手段を改善するが、実験へ人を回した間は製品産出が減る。
- **現地供給を育てる街**: 月や火星の分析・採氷・電源・造形工房へ先行投資する。
  輸入する完成品を減らせる一方、資金と担当者が現地設備に必要になる。

3例は排他的な職業・固定コースではなく、その時点の投資配分。
すべてを建てる正解を作らず、規模と地形によって後回しにする設備が違うようにする。

## 7. 解放の楽しさと、街の読みやすさ

- 未解放の施設名・シルエット・将来の建設予約地は地図や一覧へ先出ししない。
  空き地は自然や普通の土地として見せる。
- 研究完了時に、解放したものと可能になる仕事を短く示し、「地図で建設」へ移れるようにする。
  現在行けない天体の設計はその理由を示し、未解放天体の地図までは開かない。
- 施設を選ぶと、建設費・工期・担当者・入力・出力・対応する仕事を見られる。
  配置プレビューで、この土地・接続先による差を具体量で確認する。
- 建設中は足場と搬入、完成時は固有の建物、稼働中は扉・照明・積み荷の動きで変化を見せる。
  休止、資材待ち、人員不足は短い表示と建物の状態で区別する。
- 全景では主要な輪郭、接写では設備・接続を見せる。小さな建物を全景で押し分けさせない。
- レベル上昇は単なる拡大だけにせず、別棟やラインの増設で表現する。
  新しい用途の解放と、同じ用途の能力増強を区別する。
- 貨物や車両の演出は、実際の入出庫・輸送・作業の状態に対応させる。
  装飾の交通を独立した生産や輸送として計算しない。

近くに同じ施設を置く一律ボーナスより、温室と回収棟、採氷と処理、工場と整備のような具体的な連携を優先する。
隣接は効率・接続費・分かりやすさの利点とし、離れた用地も物流設備や追加負担で使える余地を残す。
建設順を一つに固定する必須の隣接パズルは増やさない。

## 8. 新しい施設を継続追加できる仕組み

プレイの共通ルールと施設ごとの内容を分ける。
既存と同じ種類の効果なら定義と外観の追加で増やし、新しい作用だけ進行処理を拡張できる形を推奨する。
単一パッケージと現在の責務分離を維持し、大規模なパッケージ分割や専用のスクリプト言語を導入しない。

| 共通の定義 | 追加時に記入・確認すること |
| --- | --- |
| 解放 | 必要研究、発見と購入の区別、旧研究との対応 |
| 配置 | 対応天体・地形・規模・併設可否・対応する親建物 |
| 建設 | 費用・資材・工期・共用作業枠 |
| 稼働 | 担当者・維持費・入力・出力・接続・休止条件 |
| 固有の役割 | 製造品、受注、調査、貯蔵、作業枠、機体整備など |
| 外観 | 本体モデル、増設位置、レベル差、建設・稼働・停止の状態 |
| 継続性 | 保存ID、旧設備との対応、完了・入出庫の重複防止 |

研究カタログは何が解放されるかを参照し、地図上の施設は一つの実体を共有する。
画面・進行・描画が別々の施設台帳を持たないようにする。
価格・工期・産出量はGameContentへ集約し、進行計算はdomainに置く。
保存はinfrastructure、操作と時刻はapplication、表示はpresentation、建物の表現はrenderingを維持する。

追加する施設のレビューでは、次の5点をそろえる。

1. 今までできなかった選択、または既存と異なる条件での利点がある。
2. 建てる場所・連携先・担当者のどれかに判断がある。
3. 輪郭や付属設備から他の施設と見分けられる。
4. 入口が循環せず、資金不足・資源不足から戻れる代替がある。
5. 保存・オフライン進行を含め、効果が地図の一つの実体へ帰属する。

この基準を満たさない細かな研究は、別棟を増やすより既設建物の改修・製法として扱う。
更新ごとに「新しい町の仕事→それを支える研究と建築→次の目的」を一組で追加すると、施設数だけが増えることを避けられる。

## 9. 導入順の提案

### 最初は12系統を軸に、建てる楽しさと効果の差を確かめる

上表の★12系統を優先候補とする。
初期の基礎研究所も地図上の施設として扱い、位置・研究者配置・共通RPの発生元を確認できるようにする。
その上で、温室・分析所・造形工房・整備棟の異なる4系統で、地図配置と固有モデル、稼働状態を画面試作する。
続いて12系統の組み合わせで、補給・電源・整備・輸送の異なる選択が成立するか比較する。
12系統を一度に導入する意味ではなく、追加する連携ごとに土地と管理負担を確かめる。
この段階でも、既存の住宅・研究・工場・宇宙港と既設の月面地区を土台として使う。

### 次に、現地の産業連携と都市の分業を広げる

原料処理、複数の電源、食品・材料事業、機体の整備・再出発を拡張する。
32候補をまとめて義務化せず、同じ投資余力で違う街・便・研究順になるかを確かめながら追加する。
軌道設備、大型計画、共同研究、人材育成はその後に扱う。

### 旧セーブの扱いは、実装前に対応表を作る

既存研究・設備への支払い・担当者・進行中の工程を引き継ぎ、移行で二重に効果を付けない。
既設設備は新しい建物の資産へ対応付け、再購入を強制しない。
満杯の都市や、同じ区画に収まらない設備への対処は先に比較する。
候補は「旧設備だけの既存敷地表示を残し、順次再配置できる方式」と「移行専用の敷地拡張」。
自動配置で住宅・地形・予約を消す方法は推奨しない。どちらを採るかはこの文書では確定しない。
現在維持している月技術の地上実証も、そのまま月面の完成設備に変換しない。

## 10. 採否を判断するための確認

実装段階では、少なくとも以下を評価する。

- 研究前には隠れ、研究完了後に建設候補へ現れ、指定した場所に工事と固有建物が残る。
- 解放した施設が、製品・供給先・仕事・輸送・作業枠のいずれかを実際に変える。
- 同じ土地・資金・人員で、収益優先、研究優先、現地供給優先の差が出る。
- 太陽光の追加と蓄電、完成品輸入と現地製造、使い切り機と再使用が、規模によって選び分けられる。
- 研究者不在の研究設備はRPを生まず、休止・稼働条件未達の設備は産出しない。
  無人運転可能な発電・採掘と、人が不足した研究設備を区別する。担当者・機体・作業枠を二重に使わない。
- 25区画の満杯状態でも、用途転換・輸入・別都市などで主要な進行と旧設備の移行を継続できる。
- 一括/分割進行、再起動、時計の前後退、保存中断で、入出庫・完成・整備・一度限り報酬が重複しない。
- 小さい横画面でも全景で用途を読み取り、接写で目的の建物を選べる。実機の描画負荷も測る。
- 最初の1時間に、新しい判断と完成した街の変化が継続する。待ち時間の延長や操作回数の増加だけで引き延ばさない。

今回実施: 現行の地区・都市・研究応用先の確認、既存企画との照合、建物・改修・機体・運用の分類、
32候補と優先12系統の机上整理、区画と外観の比較、文書の件数・研究ID・リンク・差分検査。
未実施: 数値バランス、経路試走、画面試作、性能測定、アプリ変更、保存移行、ゲームテスト、iOS/Android検証。
文書のみのため `bash tools/check.sh` とモバイルビルドは実行しない。コミット・push・追加配信も行わない。

次の判断は、区画内の併設方式と優先施設の採否。
採用後に、最小構成の街と供給・輸送の数値試算、旧98応用先との対応表へ進む。
火星復元・全球ED・周回継承・収益化の未決定ルールは今回の案で確定しない。
